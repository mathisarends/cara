# Cara Gateway Python client

`gateway_client` is a fully typed, code-generated Python client for the Cara
Gateway's JSON-RPC 2.0 WebSocket API. Its models, namespace clients, and top-level
client class are generated by `rpckit`'s codegen from
`gateway/server/schema/gateway.openrpc.json`. It has no import, build, or runtime
dependency on the `gateway-server` workspace package — only `rpckit`, `pydantic`, and
`websockets`. Any process that can reach the Gateway over WebSocket — the
[`cli`](../../cli) client, the voice pipeline, or a future channel — can depend on
this package alone.

## Quickstart

```python
import os

from gateway_client import GatewayClient, WebSocketTransport

transport = await WebSocketTransport.connect(
    "ws://127.0.0.1:8000/v1/gateway",
    token=os.environ["CARA_GATEWAY_TOKEN"],
)
async with GatewayClient(transport) as client:
    session = await client.session.open(channel={"name": "cli"}, metadata={"app": "ios"})
    await client.subscription.subscribe(session_id=session.id)
    await client.turn.start(session_id=session.id, message="Hallo")

    async for notification in client.notifications():
        match notification.params:
            case event if event.type == "chat.delta":
                print(event.text, end="")
            case event if event.type == "turn.completed":
                break
```

Every RPC method is namespaced on the client by its method prefix
(`client.session.*`, `client.subscription.*`, `client.turn.*`), takes keyword-only parameters, and
returns a parsed Pydantic model — never a raw `dict`. `client.notifications()`
streams every server-pushed event (chat deltas, tool calls, turn lifecycle) as
a validated `SessionEventNotification`.

## Regenerating the client

Whenever the Gateway's RPC surface changes, regenerate the schema and the
client together, from the workspace root:

```bash
uv run cara-gateway-schema
uv run --package gateway-codegen cara-gateway-client-generate \
  gateway/server/schema/gateway.openrpc.json
```

The first command introspects the Gateway's RPC method registry and writes
`gateway/server/schema/gateway.openrpc.json` (see [`gateway-server`](../server) for how
that introspection works, via `rpckit.schema`). The second reads that file
and regenerates the complete source package under
`gateway/client/src/gateway_client/`. Generator implementation and templates
live separately in [`gateway/codegen`](../codegen).

Run the generator with `--check` in CI to fail the build when the checked-in
client has drifted from the schema:

```bash
uv run --package gateway-codegen cara-gateway-client-generate \
  gateway/server/schema/gateway.openrpc.json --check
```

`--check` writes nothing; it exits non-zero the moment any generated file
would differ from what is on disk, which is exactly what catches an OpenRPC
change that was never followed by a regeneration.

## What gets generated

The separate [`gateway-codegen`](../codegen) package combines
`rpckit.codegen.render_python_client` with Gateway-specific Jinja2 templates.
It produces every Python file below with a "do not edit" header:

| Output | Generated from |
| --- | --- |
| `models.py` | Every schema under `components.schemas`: enums (`StrEnum`/`IntEnum`), Pydantic models (`RpcModel` subclasses with `extra="forbid"` where the schema itself forbids additional properties), discriminated unions built from OpenRPC `discriminator` blocks (e.g. `SessionEvent`, the `type`-discriminated union all chat/tool/turn events belong to), and an `RpcMethod` enum with one member per RPC method name. |
| `client.py` | The top-level `GatewayClient`: one attribute per namespace, `notifications()` (a `TypeAdapter(SessionEventNotification)`-validated stream), and `close()`/async context-manager support. |
| `namespaces/<name>.py` | One class per method-name prefix (`session.*` → `SessionClient`, `turn.*` → `TurnClient`). Each RPC method becomes one `async def` that builds its params model, calls `RpcTransport.request()`, and validates the result. |
| `namespaces/__init__.py` | Re-exports every namespace class. |
| `transport.py` | The Gateway WebSocket implementation of `RpcTransport`, rendered from a Jinja2 template. |
| `__init__.py` | The public API, combining generated RPC types with transport and error exports. |

Adding a Gateway RPC method or changing a wire model never requires touching
the client source package by hand — only running the two commands above.

## Transport and error handling

```python
from gateway_client import RpcClientError, RpcRemoteError, RpcTransport, RpcTransportError
```

`RpcTransport` and the client error types (`RpcClientError`, `RpcRemoteError`,
`RpcTransportError`) come straight from `rpckit.client` — this package only
re-exports them. `WebSocketTransport` is generated from the codegen package's
Jinja2 template as a concrete implementation of `RpcTransport` over
`websockets`. Every namespace method
calls through the transport, so a test can swap in a fake one without
touching generated code.

`WebSocketTransport` frames each call as a JSON-RPC 2.0 request with an
incrementing integer `id`, resolves it against a pending `asyncio.Future` when
the matching response arrives, and routes every message *without* an `id`
into the notification queue instead — that is the distinction between an RPC
response and a server-pushed event on this one WebSocket connection.

| Error | Raised when |
| --- | --- |
| `RpcRemoteError` | The Gateway responds with a JSON-RPC `error` object; carries `code`, `message`, and optional `data`. |
| `RpcTransportError` | The WebSocket connection closes or fails while a request is pending or being awaited. |

On disconnect, every still-pending request is failed with an
`RpcTransportError` and the notification stream ends, so a caller awaiting
either a request or `async for` over `notifications()` observes the drop
instead of hanging.

## Package layout

```text
gateway/client/src/gateway_client/
├── __init__.py       generated public exports
├── transport.py       generated WebSocket transport
├── client.py             GatewayClient (generated)
├── models.py             wire models, enums, discriminated unions (generated)
└── namespaces/
    ├── __init__.py       namespace re-exports (generated)
    ├── automation.py       AutomationClient: list, get (generated)
    ├── session.py         SessionClient: create, open, get (generated)
    ├── subscription.py     SubscriptionClient: subscribe, unsubscribe (generated)
    └── turn.py             TurnClient: start, cancel (generated)
```
